# Phase 14 — k3s, kubectl, Helm, kube-prometheus-stack

**Don't start this until you've spent a month or more genuinely operating the Compose
stacks** — adding/removing services, restoring a backup, reading logs under pressure.
Per `docs/pacing-schedule.md`, this is deliberately the last phase.

## Goal

A lightweight, single-node Kubernetes cluster with its own observability stack, as a
learning environment separate from (and initially competing for ports with) the Docker
Compose stacks.

## Prerequisites

- Comfortable with Docker Compose day-to-day operations
- A plan for the port conflict below — decide before you start, don't discover it live

## Port conflict, read first

k3s's built-in Traefik ingress and the Compose Traefik (phase 11) both want ports
80/443. Grafana (phase 8, or k3s's own if you install kube-prometheus-stack) both want
3000. Pick one:

- **Stop the Docker stacks** while learning k3s (simplest — this repo assumes this
  option, since the point right now is learning k3s, not running both in production).
- Or install k3s with its bundled Traefik disabled (`--disable traefik`) and put a
  from-scratch ingress controller on different ports — more advanced, not covered here.

## Steps

1. Stop the Compose stacks that hold 80/443/3000 to avoid the conflict:
   ```
   ssh homelab 'cd ~/homelab/traefik && docker compose down'
   ssh homelab 'cd ~/homelab/monitoring && docker compose down'
   ```
2. Install k3s (check https://docs.k3s.io for current install command/flags):
   ```
   curl -sfL https://get.k3s.io | sh -
   ```
3. Set up `kubectl` access (k3s ships its own, or copy the kubeconfig to use your own
   kubectl):
   ```
   sudo cat /etc/rancher/k3s/k3s.yaml
   ```
   Copy this to `~/.kube/config` on the Omarchy laptop (adjusting the server address to
   the lab's Tailscale IP or `homelab`), or just `ssh homelab` and use `kubectl`/`k3s
   kubectl` there directly.
4. Install Helm (check https://helm.sh/docs/intro/install/ for current instructions):
   ```
   curl https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3 | bash
   ```
5. Install kube-prometheus-stack via Helm:
   ```
   helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
   helm repo update
   helm install kube-prometheus-stack prometheus-community/kube-prometheus-stack -n monitoring --create-namespace
   ```

## Verification

- `kubectl get nodes` — over Tailscale, off home Wi-Fi — shows the single node Ready.
- `kubectl get pods -n monitoring` shows the kube-prometheus-stack pods Running.
- Port-forward or expose Grafana from the k3s install and confirm it renders, same
  milestone as phase 8 but on Kubernetes this time.

## Troubleshooting

- **k3s won't bind port 80/443**: confirm the Compose Traefik is actually stopped
  (`docker ps`), not just the container renamed.
- **`kubectl` "connection refused"**: check the server address in your kubeconfig
  matches how you're reaching the lab (Tailscale IP/hostname vs. `127.0.0.1`, which only
  works run locally on the lab machine itself).
- **When you're done experimenting**: `k3s-uninstall.sh` (installed alongside k3s)
  removes it cleanly so you can bring the Compose stacks back up on 80/443/3000.
